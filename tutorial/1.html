第1章：言語別 コメントアウトの書き方一覧

コメントアウトは、プログラムの実行結果に影響を与えずに「メモを残す」「一時的に処理を無効化する（デバッグ）」ために使います。言語ごとに書き方（シンタックス）が異なるため、正しく使い分けましょう。

言語 / ファイル 単一行コメント 複数行コメント 主な用途・特徴
HTML <!-- コメント --> 構造の区切り（例：<!-- メイン領域 -->）や要素の一時的非表示。
CSS /* コメント */ スタイルのセクション分け（例：/* ヘッダー装飾 */）や記述の切り替え。
JavaScript // コメント /* コメント */ 処理の目的説明、一時的な処理無効化。1行記述は // が主流。
Markdown <!-- コメント --> ドキュメントプレビュー時に画面表示させたくない備忘録やメモ。

具体的なコード例

1. HTMLのコメント
<!-- これは画面に表示されないHTMLコメントです -->
<div class="header">
  <!-- <h1>一時的に非表示にしたいタイトル</h1> -->
  <p>ようこそ！</p>
</div>
2. CSSのコメント
/* ================================
   ボタンのスタイル定義
   ================================ */
.btn-primary {
  background-color: #2563eb; /* ブランドカラーの青 */
  /* color: red;  ← デバッグ用に古い設定を残す */
  color: #ffffff;
}
3. JavaScriptのコメント
// 1行コメント：次の処理の「目的」を書く
const maxRetryCount = 3; 

/* 
 * 複数行コメント：
 * 複雑なアルゴリズムの解説や、仕様の背景を
 * 詳しく書き残すときに使用します。
 */
function calculateTax(price) {
  return price * 1.1; // 消費税10%を計算
}
4. Markdown (.md) のコメント
<!-- MarkdownでもHTMLと同じ形式でコメントアウトが可能です -->
# ドキュメントタイトル

<!-- TODO: あとでこの章に図解画像を追加する -->
ここは本文テキストです。
⚡️ ショートカットキーで一瞬でコメント化！
VS Codeなどの多くのエディタでは、行を選択して Ctrl + /（Macは Cmd + /）を押すだけで、その言語に合わせたコメントアウトが自動適用されます。

第2章：GitHub Browser（ブラウザ操作）でのプルリクエスト手順

フォーク（Fork）をせず、チームの共通リポジトリ上で「ブランチを作成 → 編集 → プルリクエスト（PR）」を送る手順です。PCのWebブラウザだけで完結するため、最もシンプルで間違いが起きにくい方法です。

1ファイルを編集する

GitHubのリポジトリファイル画面で、右上にある鉛筆マークから「edit」と書かれたボタンをクリックします。

2保存する

右上の緑色のボタン Commit changes...ボタンを押します。

3branchを作成する

選択肢Create a new branch for this commit and start a pull requestを選択します。デフォルトでは選択されないので注意！入力欄には適当な名前を入力します。

4編集を実行

緑色のCommit」ボタンをクリックします。

5PRのタイトルと内容を書いて送信する

タイトルに変更内容の概要（例: [機能追加] トップページにジャンプボタンを追加）を書きます。本文に「何を変更したか」「確認してほしい点」を書いて、緑色の「Create pull request」ボタンを押せば完了です！

💡 なぜ main を直接編集せず、ブランチを作るの？
main は「完成された動く状態」を保つ場所です。個別ブランチで作業することで、途中でバグっても他の人に影響を与えず、レビューを通して安全に合体（マージ）できるようになります。

第3章：JavaScriptの `if` 文における `return` の徹底解説

関数のなかで `return` を使うと、「呼び出し元に値を返す」だけでなく、「その時点で関数の実行を終了して抜け出す」という役割を果たします。これを利用したのが「早期リターン（ガード節）」です。

1. `return` の基本的な動き

`return` が実行された瞬間、その下にあるコードは一切実行されずに関数が終わります。

function testReturn() {
  console.log("① ここは実行される");
  return; // ここで関数終了！
  console.log("② ここは絶対に実行されない");
}

2. `if` と `return` を組み合わせる「早期リターン（ガード節）」とは？

不正な条件や例外的なケースを `if` 文と `return` で先にはじき出すテクニックです。

❌ 悪い例：if / else でネスト（入れ子）が深くなっているコード

条件が重なると `if` の中に `if` が入って右にどんどんズレていき、どれが何の処理か分からなくなります。

// プレイヤーが動く処理
function movePlayer(player) {
  if (player != null) {
    if (player.isAlive == true) {
      if (player.stamina > 0) {
        // メインの移動処理（ここに行き着くまでが長い！）
        player.x += 10;
        player.stamina -= 1;
      } else {
        console.log("スタミナ切れ！");
      }
    }
  }
}
⭕️ 良い例：`return` を使った早期リターン（ガード節）

ダメな条件（エラーや非対象）を先頭で即座に `return` して追い出すことで、メイン処理が真っ直ぐ見やすくなります。

// 早期リターンを適用したコード
function movePlayer(player) {
  // ① プレイヤーが存在しないなら即終了
  if (!player) return;

  // ② 死亡しているなら即終了
  if (!player.isAlive) return;

  // ③ スタミナがないなら警告を出して即終了
  if (player.stamina <= 0) {
    console.log("スタミナ切れ！");
    return;
  }

  // ★ メインの処理（ネストがなくなり真っ直ぐ読める！）
  player.x += 10;
  player.stamina -= 1;
}
🎯 ガード節を使う 3 大メリット
  1. ネストが浅くなる： インデント（字下げ）が減り、コードが横に伸びない。
  2. エラーを未然に防ぐ： `null` や `undefined` の要素を真っ先にはじくため、クラッシュしにくい。
  3. 読むのが楽： 「この条件なら何もしない」というルールが関数の冒頭で一目でわかる。
