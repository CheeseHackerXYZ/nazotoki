第1章：基本文法 & データ型（Core Mechanics）

1.1 変数宣言（const / let / var）とスコープの完全解説

JavaScriptにおける変数宣言には const, let, および歴史的に使われてきた var の3種類が存在します。現代のJavaScript開発（ES6以降）では const を基本とし、再代入が必要な場合のみ let を選択するのが鉄則です。

キーワード スコープ (Scope) 再代入 再宣言 ホイスティング (巻き上げ) 挙動
const ブロックスコープ { } 不可 不可 宣言のみ巻き上げ（TDZによりアクセス不可）
let ブロックスコープ { } 可能 不可 宣言のみ巻き上げ（TDZによりアクセス不可）
var (非推奨) 関数スコープ / グローバル 可能 可能 宣言が巻き上げられ undefined で初期化される

一時的死域（Temporal Dead Zone: TDZ）とは？

let や const で宣言された変数は、コードの実行前にスコープの先頭に巻き上げられますが、実際の宣言行に達するまで「初期化」されません。このスコープ先頭から宣言行までのアクセスが禁止されている区間をTDZ（Temporal Dead Zone）と呼びます。未初期化の変数にアクセスしようとすると ReferenceError が発生します。 

// TDZの概念を示すコード例
function example() {
  // --- 変数 value の TDZ 開始 ---
  console.log(value); // Uncaught ReferenceError: Cannot access 'value' before initialization
  
  const value = "Hello JavaScript"; // --- TDZ 終了 ---
  console.log(value); // "Hello JavaScript"
}

1.2 基本的なデータ型と型変換（Type System & Coercion）

JavaScriptは動的型付け言語であり、値は7つのプリミティブ型とオブジェクト型に大別されます。

  • Primitive Types（不変・値渡し）: String, Number, BigInt, Boolean, Undefined, Null, Symbol
  • Object Type（可変・参照渡し）: Object, Array, Function, Date, RegExp など
⚠️ `typeof` 演算子の歴史的罠と `NaN` の特殊性
  • typeof null === "object" : JS最初の実装時のバグが後方互換性のために残された有名な挙動です。null かどうかの判定は val === null を使用します。
  • typeof NaN === "number" : `NaN` (Not a Number) は数値型として定義されています。自分自身と等しくない唯一の値（NaN === NaN は false）であるため、判定には Number.isNaN(val) を使います。

明示的型変換 と 暗黙の型変換（Type Coercion）

JavaScriptでは演算子の種類や文脈によって暗黙の型変換が自動発生します。バグの原因になりやすいため、明示的型変換を徹底します。 

// --- 暗黙の型変換 (Implicit Coercion) の例 ---
"5" + 2      // "52"  (数値2が文字列に変換され連結)
"5" - 2      // 3     (文字列"5"が数値5に変換され減算)
if ("hello") {} // 真偽値文脈により Truthy と判定される

// --- 明示的型変換 (Explicit Coercion) ---
const num = Number("123");      // 123 (数値変換)
const str = String(456);        // "456" (文字列変換)
const bool = Boolean(1);        // true (Boolean変換)
const parsed = parseInt("10px", 10); // 10 (基数を明示した整数解析)

Truthy と Falsy の一覧

条件文で false と評価される Falsy な値 は以下の8種類のみです。これら以外はすべて Truthy（true と評価） です。

Falsy な値（全8種）
false, 0, -0, 0n (BigIntのゼロ), "" (空文字), null, undefined, NaN

1.3 制御構文（Control Structure）

条件分岐（if / else / switch / 三項演算子）

// 三項演算子 (簡潔な条件付き代入)
const userRole = "admin";
const accessLevel = userRole === "admin" ? 10 : 1;

// switch文 (厳密等価比較 === が行われる)
switch (userRole) {
  case "admin":
    setupAdminPortal();
    break; // breakが無いとフォールスルー発生
  case "editor":
    setupEditorPortal();
    break;
  default:
    setupUserPortal();
}

ループ構文の使い分け（for, for...of, for...in）

  • for (let i = 0; i < N; i++): インデックスによる精密なループ制御。
  • for...of: 配列や文字列などイテラブル（反復可能）オブジェクト要素の走査（最も推奨）。
  • for...in: オブジェクトの列挙可能プロパティ（キー）の走査（※配列には非推奨）。
const fruits = ["Apple", "Banana", "Orange"];

// for...of (値の取得)
for (const fruit of fruits) {
  console.log(fruit); // "Apple", "Banana", "Orange"
}

// オブジェクトに対する for...in (キーの取得)
const config = { theme: "dark", lang: "ja" };
for (const key in config) {
  console.log(`${key}: ${config[key]}`);
}

第2章：オブジェクトの徹底理解（Objects & Memory Architecture）

2.1 プロパティの取得・追加・削除・階層アクセス

JavaScriptのオブジェクトはキー（文字列またはSymbol）と値のコレクションです。 

const userProfile = {
  id: 101,
  "user-name": "Taro Tanaka", // 特殊文字を含むキー
  settings: {
    notifications: { email: true }
  }
};

// 1. ブラケット記法 (動的キーや特殊文字列キーに必須)
const keyName = "id";
console.log(userProfile[keyName]); // 101
console.log(userProfile["user-name"]); // "Taro Tanaka"

// 2. プロパティの削除
delete userProfile.id;

// 3. オプショナルチェイニング (?.) と Null合体演算子 (??)
// 存在しないプロパティアクセスで TypeError を防ぐ
const smsEnabled = userProfile.settings?.notifications?.sms ?? false;
console.log(smsEnabled); // false (undefined のため右辺のデフォルト値が評価される)

2.2 メソッド定義と `this` の挙動原理

オブジェクト内の関数を「メソッド」と呼びます。メソッド内で使われる this の参照先は、呼び出し方（実行時の文脈）によって動的に決定されます。 

const counter = {
  count: 0,
  // 通常のメソッド定義 (this は counter を指す)
  increment() {
    this.count++;
    console.log(this.count);
  },
  // アロー関数メソッド (自身の this を持たないため親スコープを指す)
  badIncrement: () => {
    // ここでの this はグローバル (window / undefined) を指してしまう！
    console.log(this.count); // undefined
  }
};

counter.increment(); // 1 (正常)

2.3 オブジェクトの分割代入・スプレッド構文 (`...`)

const employee = {
  empId: "E-99",
  fullName: "Hanako Sato",
  department: "Engineering",
  salary: 500000
};

// 1. 分割代入 (エイリアス設定 & デフォルト値)
const { fullName: name, department, role = "Staff" } = employee;
console.log(name, department, role); // "Hanako Sato", "Engineering", "Staff"

// 2. スプレッド構文によるイミュータブルな更新 (残りのプロパティ収集も併用)
const { salary, ...publicInfo } = employee; // salary を除外した新オブジェクト
const updatedEmployee = {
  ...publicInfo,
  department: "R&D", // 特定フィールドの上書き
  updatedAt: new Date()
};

2.4 値渡し vs 参照渡し & メモリ構造（Shallow vs Deep Copy）

JavaScriptにおいて、プリミティブ型はスタックメモリ上にデータそのものが格納されます（値渡し）。一方、オブジェクト型はヒープメモリ上に実体が配置され、変数にはそのメモリ領域を示す「参照アドレス」が割り当てられます（参照渡し）。

💡 シャローコピー（浅いコピー）とディープコピー（深いコピー）の差
  • シャローコピー (Object.assign() / { ...obj }): 1階層目のプロパティのみを複製。2階層目以降のオブジェクトの参照アドレスは共有されたままになります。
  • ディープコピー (structuredClone()): すべての階層のオブジェクトを再帰的に完全独立複製します。
const original = {
  title: "JS Textbook",
  author: { name: "Alice" }
};

// --- シャローコピー ---
const shallow = { ...original };
shallow.title = "Python Textbook"; // original.title は変化しない
shallow.author.name = "Bob";          // ⚠️ original.author.name も "Bob" に書き換わる！

// --- ディープコピー (モダン標準) ---
const deep = structuredClone(original);
deep.author.name = "Charlie";       // original.author.name は "Bob" のまま保持される

第3章：関数の深掘り（Advanced Functions & Scope）

3.1 関数宣言 / 関数式 / アロー関数の比較と使い分け

種類 構文 巻き上げ (Hoisting) `this` の束縛 `arguments`
関数宣言 function fn() {} あり (呼び出しが上でも機能) 呼び出し元に動的決定 あり
関数式 const fn = function() {} なし (変数宣言のみ巻き上げ) 呼び出し元に動的決定 あり
アロー関数 const fn = () => {} なし 静的（定義時の外側スコープを継承） なし 
// アロー関数における this のレキシカルスコーピング
class Timer {
  constructor() {
    this.seconds = 0;
  }
  start() {
    // アロー関数を使用することで this が Timer インスタンスに固定される
    setInterval(() => {
      this.seconds++;
      console.log(this.seconds);
    }, 1000);
  }
}

3.2 引数設計（デフォルト引数・残余引数 ...args）

// デフォルト引数と残余引数の組み合せ
function createReport(title = "無題レポート", category = "General", ...dataPoints) {
  return {
    title,
    category,
    data: dataPoints,
    totalCount: dataPoints.length
  };
}

const report = createReport("月次売上", "Finance", 100, 250, 400);
console.log(report.totalCount); // 3

3.3 返り値設計パターン・クロージャ（Closure）・高階関数

アーリーリターン（Early Return）パターン

ネスト（深さ）を浅く保ち、コードの可読性と保守性を高めるために、条件を満たさない場合は早い段階で return して処理を抜ける設計技法です。 

// アーリーリターンによる可読性向上
function processOrder(order) {
  if (!order) return { success: false, reason: "No order data" };
  if (!order.paymentReceived) return { success: false, reason: "Unpaid" };
  if (order.items.length === 0) return { success: false, reason: "Empty cart" };

  // 正常系のメイン処理
  return { success: true, orderId: order.id };
}

クロージャ（Closure）の実用パターン

クロージャとは、関数とその関数が宣言されたレキシカル環境（外側の変数スコープ）の組み合わせです。外側の関数が実行を終えた後でも、内部関数からその外側変数を保持・参照し続けることができます。これにより「データの隠蔽（カプセル化）」を実現できます。 

// カウンターを作成するクロージャファクトリ関数
function createCounter(initialValue = 0) {
  let count = initialValue; // 外部から直接アクセス不能なプライベート変数

  return {
    increment() {
      count++;
      return count;
    },
    decrement() {
      count--;
      return count;
    },
    getValue() {
      return count;
    }
  };
}

const myCounter = createCounter(10);
console.log(myCounter.increment()); // 11
console.log(myCounter.count);       // undefined (直接改ざん不可能)

第4章：ブラウザ機能 & DOM操作（DOM API Deep Dive）

4.1 DOMの選択・変更・スタイル操作

ブラウザはHTML文書を解析し、JavaScriptからアクセス可能なノードツリー（DOM: Document Object Model）を構築します。 

// 1. 要素取得 (querySelector を推奨)
const header = document.querySelector("#main-header");
const cards = document.querySelectorAll(".card"); // NodeList (配列風オブジェクト)

// 2. テキスト更新: textContent vs innerHTML セキュリティ
// ユーザー入力を描画する際は XSS 対策のため必ず textContent を使用する
header.textContent = "安全なテキスト挿入";

// 3. classList API による安全な CSS クラス操作
header.classList.add("sticky", "shadow");
header.classList.remove("hidden");
header.classList.toggle("dark-theme");
const isActive = header.classList.contains("active");

4.2 DOMの動的生成・挿入・パフォーマンス最適化

DOM変更操作はブラウザの「再計算（Reflow）」「再描画（Repaint）」を引き起こすため、頻繁なDOM操作はパフォーマンス低下の原因になります。DocumentFragment を使うことで、一括挿入が可能です。 

const container = document.querySelector("#item-list");
const fragment = document.createDocumentFragment(); // メモリ上の仮想コンテナ

const itemsData = ["Item A", "Item B", "Item C"];

itemsData.forEach(text => {
  const li = document.createElement("li");
  li.className = "list-item";
  li.textContent = text;
  fragment.appendChild(li); // フラグメントに追加 (まだ画面は描画されない)
});

// 最後に1回だけ実際の DOM に追加 (リフローは1回のみ)
container.appendChild(fragment);

第5章：ブラウザイベント全網羅（DOM Events Mastery）

5.1 イベント伝播モデル（キャプチャリング & バブリング）

DOMイベントが発生すると、イベントオブジェクトは3つのフェーズを通って伝播します。

  1. キャプチャリングフェーズ（Capturing Phase）: window からターゲット要素に向かって下降。
  2. ターゲットフェーズ（Target Phase）: 実際にイベントが発生した要素に到達。
  3. バブリングフェーズ（Bubbling Phase）: ターゲット要素から window に向かって上昇（標準のイベントリスナーはこのフェーズで発火）。

5.2 カテゴリ別・全イベント完全リファレンス

1. マウス & ポインター系イベント (Mouse & Pointer)

イベント名 発火タイミング 主要プロパティ / 活用例
click / dblclick クリック / ダブルクリック時 e.clientX, e.clientY (画面座標)
pointerdown / pointerup ポインター（マウス/ペン/タッチ）の押し込み/解放 マウス・タッチを統合処理するモダンAPI
pointermove ポインターの移動時 ドラッグ＆ドロップ、キャンバス描画
contextmenu 右クリックまたは長押し時 e.preventDefault() で独自メニュー表示

2. キーボード系イベント (Keyboard)

e.key は入力された「文字内容」（言語環境に依存）、e.code はキーボード上の「物理キー位置」（QWERTY配列依存）を取得します。ゲームの操作キーなどには e.code を用いるのが一般的です。 

document.addEventListener("keydown", (e) => {
  if (e.code === "KeyW" || e.code === "ArrowUp") {
    movePlayerForward();
  }
  if (e.key === "Enter" && e.ctrlKey) {
    submitFormViaShortcut(); // Ctrl + Enter ショートカット
  }
});

3. フォーム & 入力系イベント (Form & Input)

  • input: <input> や <textarea> の値が変更されるたびにリアルタイム発火。
  • change: フォーカスが外れるか選択値が確定したタイミングで発火。
  • submit: <form> 送信時に発火（通常は e.preventDefault() を呼び出しSPA化）。
  • focus` / `blur: 要素がフォーカスを得た/失った時（バブリングしない）。
const searchInput = document.querySelector("#search-input");
searchInput.addEventListener("input", (e) => {
  console.log("リアルタイム入力値:", e.target.value);
});

4. ウィンドウ & ビューポート系イベント (Window & Viewport)

  • DOMContentLoaded: HTMLの解析が完了しDOMツリーが完成した時点で発火（画像等のロード待ちなし）。
  • load: HTML、画像、CSS、外部JSなど全ての全リソースが読み込み完了した時点で発火。
  • resize / scroll: ウィンドウサイズ変更時やスクロール時（発火頻度が高いためデバウンス/スロットル必須）。

5. タッチ & ドラッグ系イベント (Touch & Drag)

  • Touch Events: touchstart, touchmove, touchend (マルチタッチ対応 e.touches)。
  • HTML Drag and Drop API: dragstart, dragover, drop
const dropZone = document.querySelector("#drop-zone");

dropZone.addEventListener("dragover", (e) => {
  e.preventDefault(); // drop イベントを許可するために必須！
});

dropZone.addEventListener("drop", (e) => {
  e.preventDefault();
  const files = e.dataTransfer.files; // ドロップされたファイル群を取得
  handleFileUpload(files);
});

5.3 イベント委譲（Event Delegation）の実践パターン

大量の動的要素に個別にイベントリスナーを登録するのではなく、親要素に1つだけリスナーを登録し、バブリングされたイベントを e.target / closest() で判定・処理するデザインパターンです。メモリ節約および動的要素への自動対応に絶大な効果を発揮します。 

// テーブル内の削除ボタンクリックをイベント委譲で一元管理
const table = document.querySelector("#data-table");

table.addEventListener("click", (e) => {
  // クリックされた要素から最も近い [data-action="delete"] 要素を検索
  const deleteBtn = e.target.closest('[data-action="delete"]');
  
  if (deleteBtn && table.contains(deleteBtn)) {
    const row = deleteBtn.closest("tr");
    const id = row.dataset.id;
    deleteRowById(id);
    row.remove();
  }
});
