【実践】 Canvas描画 & レンダリング

Standard to Advanced Bridge

標準的なDOM操作から一歩踏み出し、ピクセル単位での描画やインタラクティブなアニメーションループを構築するフェーズです。ここで培うレンダリングの知識は、複雑なUIや物理演算の実装に直結します。

1. Canvas APIの基礎と初期化

HTMLの<canvas>要素を取得し、2Dコンテキストを呼び出すことで描画の準備が整います。高解像度ディスプレイ（Retina等）に対応するためのスケーリングも重要です。

const canvas = document.querySelector('#gameCanvas');
const ctx = canvas.getContext('2d');

// 画面サイズへの追従
canvas.width = window.innerWidth;
canvas.height = window.innerHeight;

// 矩形の描画テスト
ctx.fillStyle = '#00f3ff';
ctx.fillRect(50, 50, 100, 100);

2. メインループとアニメーション

requestAnimationFrameを使用し、ディスプレイのリフレッシュレートに同期した滑らかなアニメーションループを構築します。

let x = 0;

function loop() {
  // 1. 画面のクリア (残像を消す)
  ctx.clearRect(0, 0, canvas.width, canvas.height);
  
  // 2. 状態の更新
  x += 2;
  
  // 3. 描画
  ctx.fillStyle = '#b535ff';
  ctx.fillRect(x, 100, 50, 50);
  
  // 次のフレームを要求
  requestAnimationFrame(loop);
}
loop();

3. 座標計算と衝突判定 (AABB)

オブジェクト同士の重なりを検知する基本アルゴリズム「AABB（Axis-Aligned Bounding Box）」の概念です。

  • X軸の重なり： (Aの左端 < Bの右端) かつ (Aの右端 > Bの左端)
  • Y軸の重なり： (Aの上端 < Bの下端) かつ (Aの下端 > Bの上端)

【応用】 Advanced JS Concepts & Architecture

Object-Oriented & Performance

規模の大きなコードベースを破綻させずに管理するための、言語の深い仕様（クラス、thisの挙動、カプセル化）や、パフォーマンス最適化を学ぶフェーズです。

1. クラスとオブジェクト指向 (OOP)

設計図となるclassを定義し、そこから実体（インスタンス）を生成します。共通のプロパティやメソッドをまとめることで、コードの再利用性が劇的に向上します。

class Entity {
  constructor(x, y) {
    this.x = x;
    this.y = y;
  }
  move(vx, vy) {
    this.x += vx;
    this.y += vy;
  }
}

// 継承 (extends) を使って拡張
class Player extends Entity {
  constructor(x, y, hp) {
    super(x, y); // 親クラスのコンストラクタ呼び出し
    this.hp = hp;
  }
}

2. thisのバインディングとアロー関数

JavaScriptにおいてthisは「呼び出し元」によって変化します。コールバック関数内で意図したthisを参照するために、アロー関数の性質を理解することが必須です。

  • 通常の関数： 呼び出された時のコンテキストに依存。
  • アロー関数： 定義された場所のスコープのthisを保持する（レキシカルスコープ）。

3. パフォーマンスとメモリ管理

不要になったイベントリスナーやオブジェクトの参照を残し続けると「メモリリーク」が発生し、動作が重くなります。また、連続発火するイベントの制御も重要です。

// スロットリング (一定間隔でのみ実行を許可する簡易実装)
let isThrottled = false;
window.addEventListener('resize', () => {
  if (isThrottled) return;
  isThrottled = true;
  
  setTimeout(() => {
    console.log('リサイズ処理を実行');
    isThrottled = false;
  }, 100);
});

【中上級】 Async Processing & Persistence

Promises, Fetch & LocalStorage

サーバーとの通信や、ローカル環境へのデータ保存など「時間の遅れ（非同期）」や「永続化」を扱う、現代のWeb開発において最も重要な領域です。

1. 非同期処理と async / await

ネットワーク通信やファイルの読み込みは、完了するまでに時間がかかります。処理をブロックせず、完了を待ってから次の処理を行うための仕組みがPromiseとasync/awaitです。

async function fetchConfig() {
  try {
    // 通信の完了を「待つ」
    const response = await fetch('/api/config.json');
    if (!response.ok) {
      throw new Error('ネットワークエラー');
    }
    const data = await response.json();
    console.log(data);
  } catch (error) {
    console.error('読み込み失敗:', error);
  }
}

2. localStorage を用いたデータ永続化

ブラウザ上にデータを保存し、ページをリロードしても消えないようにします。保存できるのは「文字列」のみであるため、オブジェクトを保存する際はJSON形式に変換する必要があります。

// セーブデータの構築
const saveData = {
  level: 5,
  inventory: ['sword', 'potion'],
  lastPlayed: Date.now()
};

// 文字列に変換して保存 (Serialize)
localStorage.setItem('myApp_save', JSON.stringify(saveData));

// データの読み込みと復元 (Deserialize)
const loadedStr = localStorage.getItem('myApp_save');
if (loadedStr) {
  const restoredData = JSON.parse(loadedStr);
  console.log('ロード完了:', restoredData.level);
}

3. Cookie と Storage の使い分け

  • localStorage: 有効期限がなく、明示的に削除するまで残る。容量が大きい（約5MB）。UIの状態やセーブデータに最適。
  • sessionStorage: タブやウィンドウを閉じると消える。一時的なフォーム入力の保持などに利用。
  • Cookie: サーバー側にもリクエストの度に送信される。セッション管理や認証トークンの保持に使用されることが多い。
