第1章：Canvas 2D Context の基礎（Fundamental Concepts）

1.1 Canvasの直感的イメージ：「画用紙」と「筆」

HTML5の <canvas> 要素は、Webブラウザ上に直接JavaScriptからグラフィックを描画するための特別な領域を提供します。初心者の方が理解しやすいように比喩を使うと以下のようになります。

  • <canvas> タグ: 画面上に置かれた「白い画用紙（額縁）」です。HTMLタグ自体は単なる描画スペースです。
  • 2D コンテキスト（ctx）: 画用紙に描くための「筆や絵の具などの文房具セット」です。色を変えたり、線を引いたりする命令はすべてこのコンテキストに対して実行します。
<!-- HTML側に画用紙を設置 -->
<canvas id="myCanvas" width=800 height=600></canvas>

<script>
  // 1. 画用紙 (canvas要素) を取得
  const canvas = document.getElementById("myCanvas");

  // 2. 筆 (2Dレンダリングコンテキスト) を取り出す
  const ctx = canvas.getContext("2d");
</script>

1.2 CSSのサイズ指定と内部解像度（属性）の決定的な違い

Canvasを扱う上で最も頻繁に陥る罠が、「HTML属性のwidth/height」と「CSSのwidth/height」の混同です。

🎨 Canvasの「内部ピクセル数」と「見た目の拡大縮小」
・HTML属性 (`canvas.width = 800`): 画用紙に存在する実際のドット数（ピクセル解像度）。
・CSSスタイル (`style="width: 400px;"`): 描画された画用紙を虫眼鏡や拡大鏡でどれくらい拡大/縮小して表示するか。
※ CSSだけで指定すると、デフォルトの 300×150 ピクセルの画用紙がびよーんと引き伸ばされ、グラフィックが極めて荒くぼやけてしまいます！

1.3 高解像度ディスプレイ（Retina / DPI）対応とリサイズ処理

スマートフォンやMacなどの高精細ディスプレイ（Retinaディスプレイ）では、1表示ピクセル（CSSピクセル）に対して物理的に2倍や3倍のドットが存在します。これに対応するには、window.devicePixelRatio を考慮して解像度を調整します。 

function setupCanvasResolution(canvas) {
  const ctx = canvas.getContext("2d");
  
  // ディバイスピクセル比を取得 (通常画面は1、Retinaなら2または3)
  const dpr = window.devicePixelRatio || 1;

  // 画面上の表示サイズ (CSSサイズ)
  const displayWidth = 600;
  const displayHeight = 400;

  // 1. Canvasの内部解像度を高画質用に倍増させる
  canvas.width = displayWidth * dpr;
  canvas.height = displayHeight * dpr;

  // 2. CSS表示サイズは固定する
  canvas.style.width = `${displayWidth}px`;
  canvas.style.height = `${displayHeight}px`;

  // 3. 描画コンテキストのスケールを合わせる (1px描画命令をdpr倍に自動拡大)
  ctx.scale(dpr, dpr);
}

第2章：描画ロジック & グラフィック表現（Graphics Engine）

2.1 Canvasの座標系と基本図形の描画

Canvasの座標系は、画面の「左上角」が原点 (x:0, y:0) です。右に行くほど X が増加し、下に行くほど Y が増加します（数学のグラフとY軸が逆向きになる点に注意してください）。

矩形（長方形）の描画

// 色の指定 (CSSと同じ形式が使用可能: "#ff0000", "rgb(0,255,0)", "rgba(0,0,0,0.5)")
ctx.fillStyle = "#4338ca";
ctx.fillRect(50, 50, 200, 100); // x:50, y:50 の位置に 幅200, 高さ100 の塗りつぶし四角形

ctx.strokeStyle = "#e11d48";
ctx.lineWidth = 4;
ctx.strokeRect(300, 50, 200, 100); // 枠線のみの四角形

2.2 パス（Path）を使ったフリー図形とベジェ曲線

パス描画は「紙の上に鉛筆を落とし、線を滑らせてから、最後に色を塗る/枠線を引く」という手順を踏みます。

パス命令の黄金順序
1. ctx.beginPath() : 「新しい図形を描き始めます」宣言（過去のパスをリセット）。
2. ctx.moveTo(x, y) : 筆を持ち上げて、指定した開始点に移動。
3. ctx.lineTo(x, y) : 現在地から指定座標へ直線を引く。
4. ctx.arc(x, y, radius, startAngle, endAngle) : 円弧・円を描く。
5. ctx.stroke() または ctx.fill() : 最後に線を描画するか、内側を塗りつぶして着色！ 
// --- 綺麗な円を描く例 ---
ctx.beginPath();
// arc(中心x, 中心y, 半径r, 開始ラジアン, 終了ラジアン)
// ※ 360度(1周) は 2 * Math.PI ラジアンです
ctx.arc(150, 250, 40, 0, Math.PI * 2);
ctx.fillStyle = "#10b981";
ctx.fill(); // 塗りつぶしを実行
ctx.lineWidth = 3;
ctx.strokeStyle = "#064e3b";
ctx.stroke(); // 輪郭線を描画

// --- ベジェ曲線 (Bezier Curve) による滑らかな曲線 ---
ctx.beginPath();
ctx.moveTo(50, 400); // 始点
// quadraticCurveTo(制御点X, 制御点Y, 終点X, 終点Y)
ctx.quadraticCurveTo(200, 300, 350, 400);
ctx.strokeStyle = "#f59e0b";
ctx.lineWidth = 5;
ctx.stroke();

2.3 グラデーションの作成

// 線形グラデーション (始点x,y から 終点x,y へ)
const gradient = ctx.createLinearGradient(0, 0, 400, 0);
gradient.addColorStop(0, "#4338ca");  // 0%地点の色
gradient.addColorStop(0.5, "#a855f7"); // 50%地点の色
gradient.addColorStop(1, "#ec4899");  // 100%地点の色

ctx.fillStyle = gradient;
ctx.fillRect(0, 0, 400, 50);

2.4 画像の読み込み・描画とスプライト（Sprite）切り出し

drawImage メソッドは、引数の数によって3種類のモードに切り替わる非常に強力な機能です。

モード 引数の数 構文と役割
基本描画 3つ ctx.drawImage(img, x, y) — 画像を等倍で配置
拡大縮小 5つ ctx.drawImage(img, x, y, width, height) — 指定サイズにリサイズして配置
スプライト切り出し 9つ ctx.drawImage(img, sx, sy, sw, sh, dx, dy, dw, dh) — 画像の一部をトリミングして描画
💡 9つの引数（スプライト切り出し）の覚え方
・sx, sy, sw, sh : ソース画像（Source）の切り出し開始位置 (sx, sy) と 幅/高さ (sw, sh)
・dx, dy, dw, dh : 転送先Canvas（Destination）の配置位置 (dx, dy) と 表示幅/高さ (dw, dh) 
const spriteImage = new Image();
spriteImage.src = "hero_character.png";

// 画像の読み込み完了を待ってから描画する必要がある
spriteImage.onload = () => {
  // キャラクター画像（スプライトシート）から 32x32px の1コマを切り出して 64x64px で描画
  ctx.drawImage(
    spriteImage,
    0, 0, 32, 32,    // ソース領域 (sx, sy, sw, sh)
    100, 100, 64, 64  // 描画先キャンバス領域 (dx, dy, dw, dh)
  );
};

第3章：アニメーション & レンダーサイクル（Animation Loop）

3.1 パラパラマンガの原理と `requestAnimationFrame`

Canvas上のアニメーションは、本質的には「パラパラマンガ」と同じです。毎秒約60回（60FPS）、画面を一度全部消して、少しだけ動かした図形を再描画することで動いているように見せます。

⚠️ なぜ `setInterval` や `setTimeout` を使ってはいけないのか？
setInterval はディスプレイの更新タイミング（リフレッシュレート）と同期しないため、画面のカクつき（ティアリング）が発生します。また、タブがバックグラウンドに隠れても動作し続けるため、バッテリーとCPUを激しく消費します。
requestAnimationFrame を使えば、ブラウザの描画タイミングと完全に同期し、非表示タブの時は自動で休止されるため滑らかで省電力になります。

3.2 メインループ（ゲームループ）の基本構造

let posX = 50;
let vx = 2; // X方向の移動速度 (Velocity)

function gameLoop() {
  // 1. 画面のクリア (前フレームの描画をリセット)
  ctx.clearRect(0, 0, canvas.width, canvas.height);

  // 2. 状態の更新 (Update)
  posX += vx;
  if (posX > 500 || posX < 50) {
    vx *= -1; // 壁に当たったら反射
  }

  // 3. 描画 (Render)
  ctx.beginPath();
  ctx.arc(posX, 150, 20, 0, Math.PI * 2);
  ctx.fillStyle = "#f43f5e";
  ctx.fill();

  // 4. 次のフレームの呼び出しを予約
  requestAnimationFrame(gameLoop);
}

// アニメーション開始
requestAnimationFrame(gameLoop);

残像エフェクト（スピード感）の演出技法

clearRect の代わりに、「半透明の黒背景」で上書き塗りつぶしを行うと、過去の描画が段階的に薄くなり、美しい光の残像軌跡を作ることができます。 

// clearRect の代わりに使用
ctx.fillStyle = "rgba(15, 23, 42, 0.2)"; // 不透明度20%の濃紺
ctx.fillRect(0, 0, canvas.width, canvas.height);

第4章：衝突判定 & インタラクション（Interactivity & Physics）

4.1 Canvas上の正確なマウス/タッチ座標の計算

Canvas上でマウスイベント（mousemove や click）を受け取ると、得られる e.clientX / e.clientY は「画面全体（ウィンドウ）」基準の座標です。Canvasの左上からの相対座標を得るには、getBoundingClientRect() でキャンバスの位置を引く必要があります。 

const mouse = { x: 0, y: 0 };

canvas.addEventListener("mousemove", (e) => {
  const rect = canvas.getBoundingClientRect();
  
  // Canvas上の正確なピクセル座標に補正
  mouse.x = e.clientX - rect.left;
  mouse.y = e.clientY - rect.top;
});

4.2 衝突判定のアルゴリズム（Physics Collision）

1. 矩形同士の判定（AABB: Axis-Aligned Bounding Box）

回転していない四角形同士が重なっているかを判定する、最も軽量で基本的な計算手法です。4つの端点（左・右・上・下）が重なっているかをブール条件で確認します。 

// 矩形 A と 矩形 B の AABB 衝突判定
function isAABBIntersecting(rectA, rectB) {
  return (
    rectA.x < rectB.x + rectB.width &&  // Aの左端 < Bの右端
    rectA.x + rectA.width > rectB.x &&  // Aの右端 > Bの左端
    rectA.y < rectB.y + rectB.height && // Aの上端 < Bの下端
    rectA.y + rectA.height > rectB.y    // Aの下端 > Bの上端
  );
}

2. 円同士の判定（ピタゴラスの定理）

2つの円の中心点間の距離 d が、両方の「半径の和（r1 + r2）」より小さければ衝突しています。ルート計算（Math.sqrt）は重いため、両辺を2乗して判定するのがプロのパフォーマンス最適化テクニックです。 

function isCircleIntersecting(c1, c2) {
  const dx = c1.x - c2.x;
  const dy = c1.y - c2.y;
  // 距離の2乗 (dx^2 + dy^2)
  const distanceSquared = dx * dx + dy * dy;
  const radiusSum = c1.radius + c2.radius;

  // ルートを計算せず、半径の和の2乗と比較することで超高速化
  return distanceSquared <= radiusSum * radiusSum;
}

4.3 実践ミニプログラム：マウス追従 & 衝突反応インタラクション

これまでに学んだすべての要素（初期化・ゲームループ・描画・マウス座標・円の衝突判定）を組み上げた完全動作品です。 

<!DOCTYPE html>
<html>
<body>
  <canvas id="gameCanvas" width=600 height=400 style="background:#0f172a;"></canvas>

  <script>
    const canvas = document.getElementById("gameCanvas");
    const ctx = canvas.getContext("2d");

    // マウス位置の円 (プレイヤー)
    const player = { x: 0, y: 0, radius: 25 };

    // 障害物の円 (ターゲット)
    const target = { x: 300, y: 200, radius: 40 };

    // マウス座標の監視
    canvas.addEventListener("mousemove", (e) => {
      const rect = canvas.getBoundingClientRect();
      player.x = e.clientX - rect.left;
      player.y = e.clientY - rect.top;
    });

    // メインループ
    function loop() {
      // 1. 画面消去
      ctx.clearRect(0, 0, canvas.width, canvas.height);

      // 2. 衝突判定
      const dx = player.x - target.x;
      const dy = player.y - target.y;
      const isHit = (dx * dx + dy * dy) <= Math.pow(player.radius + target.radius, 2);

      // 3. ターゲット描画 (衝突時は赤、通常時は青)
      ctx.beginPath();
      ctx.arc(target.x, target.y, target.radius, 0, Math.PI * 2);
      ctx.fillStyle = isHit ? "#ef4444" : "#3b82f6";
      ctx.fill();

      // 4. プレイヤー描画
      ctx.beginPath();
      ctx.arc(player.x, player.y, player.radius, 0, Math.PI * 2);
      ctx.fillStyle = "rgba(255, 255, 255, 0.8)";
      ctx.fill();

      requestAnimationFrame(loop);
    }

    requestAnimationFrame(loop);
  </script>
</body>
</html>
